# PRD：85 个副业点子内容质量优化（已合并）

状态：已合并，统一以 [副业机会质量、落地与探索升级](PRD-opportunity-quality-and-exploration-upgrade.md) 为准。本文件保留作为历史草案，不再单独实施。

审计日期：2026-10-24（Asia/Shanghai）

## 1. 审计结论

当前 `ideas/INDEX.md` 有 85 个点子，现有质量测试通过，说明每条记录基本具备：具体来源、服务对象与问题、赚钱方式、个人匹配、未知项、反证/替代、下一步和历史。

但现有检查主要是“关键词存在检查”，不能判断内容是否具体、证据是否支撑结论、当前性是否足够、获客是否可行。

本次全量静态审计发现：

| 项目 | 结果 | 质量含义 |
| --- | ---: | --- |
| 点子总数 | 85 | 当前有效入库规模 |
| E1 / E2 / E3 | 44 / 6 / 32 | E3 仍主要表示意向、报价或采购信号，不等于付款 |
| 待验证 / 候选 / 搁置 | 74 / 10 / 1 | 候选数量偏多，但精选仍为空 |
| 证据文字含历史信号 | 29 | 需要区分当前机会与历史案例 |
| 明确提及获客 | 45 | 约半数尚未形成行动路径 |
| 明确提及渠道 | 13 | 获客位置和入口严重不足 |
| 明确提及探索周期 | 9 | 不能支持按方向制定探索计划 |
| 明确提及工时 | 46 | 仍有大量交付负担未知 |
| 明确提及交付结果 | 8 | 交付可行性证据不足 |
| 明确提及复购 | 7 | 持续收入假设普遍未核验 |
| 索引中的 E3 未被当前规则识别 | 3 | `E3历史`、`E3付费意向` 等中文紧贴写法造成统计误差 |

结论：下一步不应继续单纯增加点子数量，而应把 85 条点子分成“可行动、需补证、仅观察、暂不适合”，并为高价值条目补齐交付边界和获客路径。

## 2. 产品目标

把“严格校验有效点子”从静态资料记录升级为可复核的机会卡片，使用户能快速回答：

1. 这是不是一个真实且当前的问题？
2. 谁可能为哪一个最小交付付费？
3. 我能通过什么渠道触达这类买方？
4. 我需要补哪一条证据，才能决定继续探索？
5. 探索多久、投入多少后，什么结果支持继续、延长或暂停？

不把内容质量优化误写成需求、成交或收益验证。

## 3. 质量模型

### 3.1 证据层与行动层分离

保留 E1–E3 证据等级，同时新增独立的内容行动状态：

- **可行动**：目标买方、具体问题、最小交付和至少一个可触达渠道均明确。
- **需补证**：方向有价值，但当前性、买方身份、工时、替代或采购结果存在关键缺口。
- **仅观察**：只有趋势、历史案例、供给推广或泛化问题，暂不足以设计小包。
- **暂不适合**：需求可能真实，但与用户当前时间、技能、预算、沟通、合规或维护条件冲突。

E3 不自动等于可行动；E1 也不自动等于不可行动。每次判断必须写理由和缺口。

### 3.2 每条点子的质量维度

每条点子新增或补齐以下维度：

| 维度 | 必须回答的问题 |
| --- | --- |
| 需求具体性 | 谁在什么场景遇到什么问题？原始讨论具体说了什么？ |
| 当前性 | 是近期需求、持续存在的问题、历史案例还是已关闭事项？ |
| 付费信号 | 是需求表达、预算、报价、选人、交付、付款还是复购？谁提供了该信号？ |
| 交付边界 | 最小服务包是什么？输入、输出、权限、返工和排除项是什么？ |
| 获客可达性 | 买方在哪里出现？如何识别？首个接触动作是什么？ |
| 个人匹配 | 时间、技能、预算、英语、会议、售后和合规分别有什么依据？ |
| 替代与反证 | 买方能否用原生功能、免费工具、内部人员或低价供给解决？ |
| 探索计划 | 建议周期、阶段目标、投入上限、继续/暂停条件是什么？ |

## 4. 现有 85 条内容的处理分层

### A 类：优先补齐并进入候选比较

优先处理当前 E3、已有买方语境、固定小包或异步交付迹象的条目，尤其是：

- `IDEA-20261021-011`、`012`、`013`：自动化实施、排障和白标交付的相邻变体，需要明确差异，避免重复竞争。
- `IDEA-20261022-036` 至 `040`：有具体买方和公开报价，但多数缺少获客路径、周期、工时或交付结果。
- `IDEA-20261022-041` 至 `046`：有近期具体需求或完成项目信号，应补交付边界、渠道和真实结果。

处理规则：先补证据，不直接升为精选；同一买方、同一问题、不同交付模式保留变体并建立关联。

### B 类：补当前性和独立性

大量 E1/E2 条目有具体问题，但仍缺近期需求、第二个独立样本或买方采购迹象。优先补：

- 当前是否仍开放；
- 是否为买方而非供应方；
- 是否有可触达渠道；
- 是否有可复制的最小交付；
- 是否存在强原生替代。

补证失败时保留历史记录，但降为“需补证”或“仅观察”，不删除。

### C 类：保留资料价值，降低行动优先级

历史 E3、已选人、已关闭项目、供给方推广和当前需求不明的条目，不能继续作为近期机会排序依据。它们保留为历史案例或反证，并显示：

- 原始信号性质；
- 时效状态；
- 未知的成交/付款结果；
- 未来重新打开的条件。

### D 类：明确暂不适合或归档观察

已有明确技能、地域、设备、频繁会议、7×24 响应、线下履约、专业资质或合规冲突的条目，保留原因后从行动候选中降级，不为了数量继续补强。

## 5. 内容优化要求

### 5.1 统一“证据摘要”格式

每条证据必须采用以下结构：

```text
对象：谁提出或经历了什么问题
原始事实：来源明确表达的内容
信号性质：事实 / 作者声称 / 研究推断
商业信号：需求 / 意向 / 报价 / 选人 / 交付 / 付款 / 复购 / 未知
时效：当前 / 历史 / 已关闭 / 日期未知
支持范围：这条证据能支持哪一个结论
不能支持：不能据此推出什么
```

禁止用“E3 采购”笼统覆盖预算、报价、选人和付款，也禁止将供应方报价写成买方预算。

### 5.2 统一“最小交付”格式

赚钱方式必须从泛化描述改为可检查的交付包：

- 买方提供什么输入；
- 交付什么输出；
- 使用什么工具或权限；
- 预计主动工时范围；
- 包含几次修正；
- 明确不包含什么；
- 适合一次性、阶段性还是持续维护；
- 仍未知的成本和风险。

### 5.3 统一“获客路径”格式

每条可行动或需补证点子至少补一条路径：

```text
目标买方：具体角色/组织
触发场景：什么时候会寻找帮助
渠道：公开采购/项目平台/专业社区/合作伙伴/内容/转介绍/线下入口
识别信号：如何判断对方可能需要
首个动作：准备什么材料或公开回复什么问题
沟通负担：异步/少量会议/频繁会议/紧急响应
停止条件：什么结果出现后不再继续
```

系统只保存研究建议和用户私人计划，不自动执行触达。

### 5.4 统一“探索周期”格式

取消固定两周限制，按方向复杂度记录：

- 简单服务：2–4 周；
- 默认探索：4–6 周；
- 复杂获客、交付或合规：6–12 周或更久。

每条计划必须有阶段目标、主动工时上限、预算上限、继续条件、延长条件和暂停条件。

## 6. 质量检查升级

现有 `src/research/idea_quality.py` 需要从“关键词存在”升级为“结构和语义提示”，但程序不替代人工判断。

### 自动阻断项

- 索引 ID、正文 ID、文件路径不一致；
- 证据等级不是 E1–E3；
- 具体来源链接不在证据段落；
- 历史表、反证/替代、未知项或下一步缺失；
- 索引证据等级无法识别，包括中文紧贴形式 `E3历史`、`E3付费意向`；
- 点子状态、个人匹配或可行动状态使用未定义值；
- 证据链接、点子标题和索引记录不一致。

### 复核提示项

- 证据只有历史或已关闭信号；
- 只有供应方报价，没有买方确认；
- 赚钱方式没有最小交付；
- 没有渠道或首个动作；
- 没有工时、沟通负担或维护边界；
- 使用“市场很大”“需求旺盛”“容易变现”等无来源泛化表述；
- 与已有点子在人群、问题和交付结果上高度相似；
- 个人匹配结论没有对应时间、技能、预算或沟通依据。

复核提示不得自动将条目判为无效，只生成待处理清单并保留人工决定。

## 7. 数据与展示变更

新增建议字段：

- `readinessStatus`：可行动 / 需补证 / 仅观察 / 暂不适合；
- `evidenceSignals`：需求、意向、报价、选人、交付、付款、复购；
- `recencyStatus`：当前、历史、已关闭、日期未知；
- `minimumDelivery`：最小交付包；
- `acquisitionPaths`：获客路径列表；
- `explorationPlan`：周期、阶段、工时、预算和退出条件；
- `qualityFlags`：机器检查和人工复核提示；
- `relatedIdeaIds`：重复、变体、上下游关联。

公开研究字段和私人计划分离。新增字段落地前先在临时库演练，不直接把 Markdown 和 SQLite 同时作为可写权威。

看板至少新增：

- 可行动 / 需补证筛选；
- 当前 / 历史 / 已关闭筛选；
- 有买方信号 / 仅供应方信号筛选；
- 有获客路径 / 缺获客路径筛选；
- 有交付边界 / 缺交付边界筛选；
- 质量问题清单；
- 证据、交付和探索周期的并排摘要。

## 8. 实施顺序

1. **审计器升级**：修复索引证据识别，增加质量提示，不改 85 条正文。
2. **批量复核清单**：生成每条点子的缺字段、时效、信号、相似和获客缺口。
3. **优先处理 A 类**：先处理 011–013、036–046，形成可比较的高价值样本。
4. **补齐统一内容模板**：证据、最小交付、获客路径、探索周期。
5. **看板展示质量状态**：先只读展示，再接正式私人状态入口。
6. **研究调度按质量缺口运行**：减少重复发现，优先当前买方、交付结果和渠道证据。

## 9. 验收标准

- 85 条点子全部通过新的结构检查；索引和正文的证据等级统计一致。
- 每条点子都有明确的质量状态和至少一个可处理的下一步。
- A 类条目全部具备最小交付、主要阻碍、建议探索周期和至少一条获客路径。
- 历史、已关闭、供给方报价、买方意向和付款结果在展示中不混同。
- 至少能识别并人工处理一批潜在重复/变体点子，不自动删除原 ID。
- 质量提示不会伪造证据、补写未知、覆盖私人状态或改变历史。
- 研究、资料和看板测试通过，资料检查失败时能指出具体点子和具体字段。

## 10. 不在本 PRD 范围

- 不为了让 85 条全部变成“可行动”而降低质量门槛。
- 不自动联系客户、发帖、投标、购买服务或执行付费实验。
- 不把 E3、报价、选人或作者收入自述改写成付款事实。
- 不删除历史点子；合并只新增关联和理由。
- 不在质量复核阶段强行切换正式数据库入口。
