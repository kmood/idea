# ADR-001：本机 SQLite 与研究资料 JSON 快照

## 状态与日期

Proposed，2026-10-15。资料与历史规格已获用户授权继续，技术方案待审阅；未安装依赖、创建业务库或迁移资料。

## 背景

单用户本机应用，局域网设备通过未来本机服务读写；需要原子历史、重复请求保护、研究/个人字段隔离，并把研究资料保存在 Git。现有仓库只有 Markdown，没有应用代码。实测本机 Python 3.14.4、sqlite3 模块可用，SQLite 3.46.1。

## 决策提案

- records-history 使用 Python 3.14 标准库（sqlite3、json、unittest、argparse 等），本模块无第三方运行依赖；不预选未来网站框架。
- `.local/records.sqlite3` 是运行时唯一写入权威；`.local/` 和其中备份、锁文件全部忽略且不作为静态资源目录。研究及个人记录在同一数据库中按表/作用域隔离，保证跨记录事务。
- Git 中的 `data/research.json` 是可恢复的研究资料快照，包含研究记录、研究历史与可导出的操作去重结果。它不是第二个自动覆盖数据库的写入口。首次或远程更新后须显式校验导入，数据库未导出变更/历史分叉必须报冲突。
- 研究快照采用确定性 UTF-8 JSON，固定字段排序及条目顺序、禁止 NaN/Infinity。内容不变则字节不变，不添加每次运行都变化的导出时间。
- 私人收藏、忽略、实验反馈、私有历史和私有操作结果不导出。以允许字段重建研究快照，不使用整库 dump 或“先全部导出再删除几个字段”。
- 原始 Markdown 保存为可追溯资料。数据层切换前继续既有手工研究流程；切换后新写入走模块入口，Markdown 视图只作阅读用途。切换需核对迁移预览及切换期间新增文件，不能仅凭修改时间覆盖。
- 本机一致性备份使用 sqlite3 Connection.backup；恢复先生成另一个数据库文件，校验后报告差异。不得覆盖运行中的数据库；实际切换前停服务、备份现库并确认目标，不在自动研究轮次恢复。

## 备选与取舍

- 仅 JSON/Markdown：Git 直接审阅方便，但跨文件历史、并发保护与原子恢复需另造机制，不选作运行时存储。
- PostgreSQL：可以满足需求，但当前单机低频写入不需要额外服务维护；保留未来替换可能。
- 直接提交 SQLite：二进制难审阅，容易夹带个人数据，拒绝。
- SQLite+研究 JSON：增加显式导入导出步骤；换取可靠本机事务与清晰仓库差异。公开快照只覆盖上次成功导出的研究数据；未导出修改和私人状态依赖本地库/备份，必须在状态输出中说明。

## 依据

[Python 3.14 sqlite3](https://docs.python.org/3.14/library/sqlite3.html) 提供连接、参数化 SQL、事务控制与备份接口；计划显式选择事务模式，不依赖默认值。[SQLite 事务文档](https://www.sqlite.org/lang_transaction.html) 描述单写者与 BEGIN IMMEDIATE；适合短事务，但必须处理忙碌。[Backup API](https://www.sqlite.org/backup.html) 支持一致性备份；不直接复制正在写入的库文件。[SQLite PRAGMA](https://www.sqlite.org/pragma.html#pragma_foreign_keys) 是外键和完整性检查依据。以上页面核验于 2026-10-15；本机版本由实际命令确认。
