# ADR-002：Agent 协作研究与有界本机执行

## 状态与日期

Proposed，2026-10-15。source-research 规格已批准，本决策及技术计划待审阅；尚未实施。

## 背景

现有 Agent 可搜索并理解讨论；仓库只有 Python 标准库实现的资料存储，Python 程序没有可直接调用的 Codex 搜索 SDK。不能把工具调用写成假接口，也不能把模型填写的“已读”当作程序读到了正文。需要可靠断点、重复执行保护和公开研究快照，同时保留本机私人状态。

## 决策提案

- 沿用 Python 3.14 和 SQLite，不安装新运行依赖、不接付费搜索或模型 API。Agent 通过现有搜索工具发现来源并提出分析，仓库程序提供有界的一轮状态机、公开网页读取及发布入口。首版自动化运行仍依赖 Agent 执行器，不是脱离执行器的独立搜索机器人。
- Agent 发起搜索前先领取带 callId 的调用预算，随后交回候选及工具来源标识。发现结果属于待核验线索；只有本机受控 Reader 实际读取到的内容才生成可用于发布的 ReadReceipt。首版不接受模型手写正文或普通 JSON 文件伪装 Reader 凭据。
- 读取器用标准库 HTTP/TLS 连接、地址检查和文本解析。优先公开 HTML、纯文本和正文型订阅；动态登录页、PDF/附件及无法定位正文的页面标为不支持或受限。可换另一个公开来源，但不能绕过限制。复杂浏览器阅读适配留待有真实可调用执行器集成时增加。
- 扩展 records-history，复用研究记录/版本/事件保存严格类型的研究元数据；本机队列、租约和缓存仍由资料层独立作用域保存，不由研究模块直接写 SQL。Provider 扩展规格单独记录。公共快照格式升级为 v2，明确兼容导入 v1，旧库升级必须在新文件进行。
- 单库研究执行权采用数据库实例标识和带递增代号的有期限租约；每个发布事务核验代号、执行者和到期时间。仅检查进程 ID 或聊天状态不足以保护被暂停后恢复的旧执行者。
- 研究内容与发布回执尽量放在同一个本地事务；跨多步发布则保存意图并逐步确认。最后才更新处置游标。普通探测/心跳留本地，不造成公开资料版本变化。

## 备选与取舍

独立商业搜索/模型 API 会新增费用、凭据和运维，目前不选。把外部工具输出全部当可信凭据实现简单，但无法区分真实正文与模型转述，不选。通用浏览器爬虫增加部署和站点适配成本，首版不引入。仅 Markdown 队列无法提供可靠事务与执行权检查，不再作为新程序的运行存储。

取舍：首版可读取范围有限，搜索和分析需要 Agent 协作；因此在线验收必须证明一轮真实工具发现→本机正文读取→引用判断→临时库发布，不能只演示导入人工写好的样例。受限站点保留失败记录，不宣称全网覆盖。

## 依据

已核验 [http.client](https://docs.python.org/3.14/library/http.client.html)、[ssl](https://docs.python.org/3.14/library/ssl.html)、[ipaddress](https://docs.python.org/3.14/library/ipaddress.html)、[robotparser](https://docs.python.org/3.14/library/urllib.robotparser.html)。这些标准库提供 HTTP、证书校验、地址分类和 robots 解析；它们不会自动完成本文的 SSRF 防护、正文识别或 Agent 工具桥接，这些必须由实现与测试证明。网页当前显示 Python 3.14.8 文档，不代表要升级本机已验证的 3.14.4。
