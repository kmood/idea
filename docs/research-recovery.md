# 研究运行恢复与公开包降级（R16）

研究运行有两种恢复来源，调用 `records.migrations.inspect_recovery(path)` 可以在继续执行前辨别它们。接口只报告可恢复的公开身份、下一步动作和本机数据计数，不返回私人状态正文、未发布请求体或正文缓存。

## 完整本机备份

`backup_local` 会在一致性事务中校验并复制公开资料、完整历史、运行与租约账本、网络节流、搜索候选、正文缓存指针、发布计划、来源进度以及私人状态历史。备份文件不包含数据库旁的 `research-cache` 目录，因此恢复到新目录时，公开 ReadReceipt 仍可证明曾读过哪些页面，但 `inspect_recovery` 会把缺失、过期、过大、非普通文件、哈希不符或无法解析的缓存标成 `missing`，下一步为 `reread`。

`restore_local` 只能写入新文件。恢复过程会更换数据库实例标识并清空旧执行持有者；原 token 随即失效。新进程必须以 `Runner.resume` 领取新租约，之后可以从保存的 PublicationManifest、本机发布计划和 SourceCheckpoint 继续相同稳定 ID。私人收藏、忽略、准备验证状态及其事件历史保持原样。

完整恢复的 `mode` 是 `local-backup`。未完成清单在本机计划仍存在时返回 `resume_local_plan`；已完成清单返回 `complete`。`localOnly` 只给出轮次、发布计划、待处理意图和私人状态的数量，用于判断恢复材料是否齐全。

## 仅公开研究包

公开包只含 ResearchArtifact 和公开资料关系。导入后可以找回 ReadReceipt、PublicationManifest、SourceCheckpoint 和已发布记录的稳定身份，但不会生成运行轮次、候选队列、发布请求计划、私人状态或未同步结果。此时 `mode` 是 `public-only`，本机计数均为零。

公开清单若仍有步骤未完成，因为请求正文不在公开包中，下一步为 `reread_and_reanalyze`。Agent 必须重新读取来源、重新验证分析，再创建新的受控发布意图；不能从摘要、目标 ID 或清单哈希反推并补造旧请求。公开断点可用于确定已经确认的位置，不能证明本机未同步的候选已经处理。

## 使用边界

恢复检查不自动发起网络请求、不领取租约、不修改个人操作，也不切换正式 Markdown 研究入口。读取缓存只验证本机可重用性；ReadReceipt 的公开 URL 和指纹继续作为历史事实，缓存缺失不会删除或改写该凭据。

R16 的测试以合成研究轮次验证所有现有运行表和私人事件历史随本机备份恢复、旧租约失效、缺缓存触发重读、相同 receipt ID 幂等恢复、部分发布继续完成，以及公开包不会伪造本机或私人数据。它不代表已经完成真实公网恢复演练。
