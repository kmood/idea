# PRD：副业机会落地与获客探索升级（已合并）

状态：已合并，统一以 [副业机会质量、落地与探索升级](PRD-opportunity-quality-and-exploration-upgrade.md) 为准。本文件保留作为历史草案，不再单独实施。

## 1. 背景与问题

当前项目已经具备来源建档、原始讨论读取、证据分级、去重、历史保存和只读看板能力。现有研究摘要显示约 85 个严格校验点子，但精选为空，说明当前瓶颈不是继续堆积点子，而是把资料转化为可执行探索。

当前主要问题：

1. 点子能入库，但缺少统一的“可落地程度”判断。
2. 已记录可能的赚钱方式，但没有形成具体的获客路径和首个触达动作。
3. 过去使用固定“两周验证”框架，无法覆盖获客周期较长、交付复杂或需要持续维护的方向。
4. 来源入口、不同平台、独立买方、采购信号和实际交付结果没有在展示层充分区分。
5. `research/STATE.md` 与索引统计存在来源数量口径差异，不能直接据此判断覆盖率。

## 2. 产品目标

把研究库升级为“机会探索工作台”，帮助用户完成：

来源资料 → 机会判断 → 可落地标识 → 获客路径 → 分阶段探索计划 → 实际反馈 → 继续/延长/暂停决策。

目标不是自动联系客户、自动成交或承诺收益，而是降低用户从研究到行动的整理成本。

## 3. 用户与约束

- 用户：后端开发背景的个人副业探索者。
- 可用时间：每天约 2 小时。
- 启动预算：一万元以内，但不自动支出。
- 可使用 AI 处理英文阅读和文字交流，尽量减少频繁英语语音沟通。
- 允许接单、产品、内容、培训和行业服务，不限制技术方向。
- 不自动发帖、私信、联系客户、购买服务或开发完整副业产品。
- 私人收藏、获客记录和实验反馈不得进入公开研究导出。

## 4. 核心定义

### 4.1 可落地标识

可落地不是“已经赚钱”，而是资料已经足以支持一个有边界的下一步。采用分层标识，不使用未经确认的固定加权总分：

- **可直接设计探索**：目标对象、问题、最小交付和至少一个可触达渠道较清楚。
- **补证后可探索**：方向有价值，但缺独立买方、预算、交付工时、权限或替代方案验证。
- **仅观察**：只有趋势、供给推广、历史案例或需求表达不足。
- **暂不适合**：证据可以成立，但当前时间、沟通、合规、成本或维护要求明显不匹配。

每个标识必须附理由、证据引用、主要阻碍和下一步动作；不得由 E3 自动推导为可落地。

### 4.2 探索周期

取消固定两周限制。默认建议周期为 4–6 周：简单服务可为 2–4 周，涉及获客、交付、合规或持续维护的方向可为 6–12 周或更久。

每个方向必须记录：阶段、主动工时上限、目标结果、继续条件、延长条件和暂停条件。周期可以延长，但不能没有阶段性退出条件。

### 4.3 获客路径

获客路径是“特定买方 → 特定渠道 → 特定问题表达 → 最小报价/交付 → 下一步动作”的可复核方案，不等同于已获得客户。

## 5. 功能范围

### M1：研究内容审计与可落地标识

输入现有来源、证据、点子、个人匹配和历史；输出结构化审计结果。

展示字段至少包括：

- 目标人群与具体问题
- 最小可售交付
- 证据等级及信号类型：需求、意向、报价、选人、交付、付款、复购
- 强替代与主要反证
- 当前个人匹配及未知项
- 可落地标识、理由、阻碍、下一步

要求：事实、作者声称、研究推断和未知项分开；审计不得修改用户私人状态。

### M2：机会扩展与点子获取矩阵

研究不再只按“行业”扩展，增加以下五种入口：

1. **问题入口**：围绕重复、延迟、返工、合规、交接、对账、维护等具体痛点找买方。
2. **买方入口**：按小企业老板、运营、代理商、教培机构、专业人员、社区组织等角色找需求。
3. **交付入口**：按固定小包、异步审计、迁移整理、白标交付、持续维护、培训辅导寻找机会。
4. **渠道入口**：公开采购、项目平台、专业社区、厂商生态、代理商合作、行业协会、线下服务商网络。
5. **反证入口**：主动查找免费替代、原生功能、自助解决、低价供给和失败案例，避免只收集正向线索。

每轮研究先选择一个覆盖缺口和一个关键未知，输出“为什么查、查哪里、什么结果会改变判断”。新来源数不作为完成指标。

### M3：获客路径设计

为每个“可直接设计探索”或“补证后可探索”的点子增加获客路径草案：

- 路径类型：公开采购、项目平台、专业社区、合作伙伴、内容展示、转介绍、线下行业入口
- 目标买方角色与触发场景
- 具体问题表述和最小服务包
- 可信证明材料：案例、样例、诊断表、演示、交付模板
- 首次接触方式：公开回复、申请项目、合作询问、内容发布或转介绍
- 预计沟通负担：异步、少量会议、频繁会议、紧急响应
- 预算/报价/付款证据及未知项
- 下一步准备动作和停止条件

系统只生成准备材料和建议，不代替用户执行外部触达。

### M4：分阶段探索计划

探索计划至少包含三个阶段：

1. **可行性阶段**：确认问题、替代和最小交付是否成立。
2. **获客阶段**：验证是否能触达目标买方并获得有效回复、询价或合作意向。
3. **交付阶段**：验证工时、权限、返工、沟通和交付边界。

每阶段记录目标、主动工时、预算、证据、结果和决策。结果只能由真实反馈或可复核交付记录更新，不能由研究推断代替。

### M5：看板与私人状态

在正式数据库入口切换后，local-web 增加：

- 可落地标识筛选
- 获客路径筛选
- 探索阶段和建议周期筛选
- 收藏、忽略、准备探索、进行中、延长、暂停
- 私人备注、反馈和下一步
- 最多 3 个方向的并排比较

在正式入口切换前，不把这些状态写入浏览器 localStorage，也不把只读 Markdown 刷新当作私人操作完成。

## 6. 数据契约建议

新增或扩展以下概念，具体字段需在独立规格中确认：

- `OpportunityReadiness`：可落地标识、理由、阻碍、引用、更新时间。
- `AcquisitionPath`：买方、渠道、问题表达、最小交付、证明材料、沟通负担、下一步。
- `ExplorationPlan`：建议周期、阶段、工时上限、预算上限、继续/延长/暂停条件。
- `ExplorationFeedback`：来源、日期、事实、结果性质、关联阶段和私人可见性。
- `CoverageMetric`：来源入口、平台、独立作者/企业、行业、人群、地域和证据进展，避免把来源条目数当作独立机会数。

所有新记录必须保留稳定 ID、历史事件和原始证据关联；研究写入不能覆盖私人字段。

## 7. 成功标准

### 内容质量

- 每个候选方向都能回答：谁的问题、最小交付是什么、凭什么判断、最大阻碍是什么、下一步查什么。
- 可落地标识与 E1/E2/E3 分开；不能把报价或作者声称显示成付款。
- 来源入口、平台、独立样本和采购结果分别统计。

### 行动质量

- 用户能从任一点子生成至少一条有边界的获客路径草案。
- 每条路径都有首个准备动作、沟通负担和停止条件。
- 用户能为每个候选方向看到建议周期，而不是统一显示两周。

### 系统质量

- 研究更新不覆盖收藏、忽略、探索计划和反馈。
- 公开导出不包含私人获客和实验信息。
- 迁移、备份、恢复和合并后稳定 ID 与历史不丢失。
- 资料统计口径有自动检查，`STATE`、索引和看板不再静默出现不同数量。

## 8. MVP 交付顺序

1. **内容审计**：先为现有点子补可落地标识、阻碍、下一步和证据信号类型。
2. **候选比较**：最多 3 个方向并排展示，加入建议探索周期和阶段目标。
3. **获客路径草案**：先支持手工记录和研究助手生成草案，不自动触达。
4. **私人状态入口**：复用 records-history，接入收藏、准备探索和反馈。
5. **研究调度优化**：按问题、买方、交付和渠道缺口安排下一轮，加入口径一致性检查。
6. **正式入口切换**：完成迁移演练、公开/私人隔离、备份恢复和回滚验证后再切换。

## 9. 不在本 PRD 范围

- 自动联系客户、发帖、私信、投标或购买服务。
- 自动判断客户一定会付费。
- 以固定分数替代证据和人的判断。
- 为了达到 200 个点子而降低准入标准。
- 立即开发完整副业产品或公网 SaaS。
- 在没有数据对账和回滚方案前切换正式数据库入口。

## 10. 待确认问题

1. 是否接受将“可落地”作为独立于证据等级的展示字段？
2. 是否把默认 4–6 周作为系统建议基线，还是只记录每个方向的个别周期？
3. 获客路径是否允许保存用户实际准备使用的渠道和私有备注？默认建议仅本机保存、不公开导出。
4. 第一批是否优先处理当前 3 个候选自动化方向，还是先从国内非技术买方中重新筛选？
