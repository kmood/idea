## 1. 背景与审计结论

现有质量测试通过，但主要验证关键词和链接存在，不能充分判断内容是否具体、证据是否支撑结论、机会是否当前、交付是否可控或买方是否可触达。

本次全量静态审计结果：

## 2. 产品目标

将研究库升级为“机会质量与探索工作台”，形成：

资料 → 内容质量审计 → 可落地判断 → 最小交付 → 获客路径 → 分阶段探索 → 实际反馈 → 继续/延长/暂停。

用户最终应能回答：

1. 这是不是一个真实且当前的问题？
2. 谁可能为哪一个最小交付付费？
3. 我能从什么渠道触达这类买方？
4. 还缺哪一条证据？
5. 应探索多久、投入多少，什么结果支持继续或暂停？

目标不是自动成交、自动触达或承诺收益，而是减少从资料到行动的整理成本。

## 3. 用户与边界

- 用户：具备整个 IT 能力范围的个人副业探索者，不预设后端开发为唯一或主要能力。
- 可用时间：每天约 2 小时。
- 启动预算：一万元以内，不自动支出。
- 可借助 AI 进行英文阅读和文字交流，尽量减少频繁英语语音沟通。
- 方向可来自接单、产品、内容、培训或行业服务，不限制技术属性。
- 不自动发帖、私信、联系客户、投标、购买服务或开发完整副业产品。
- 收藏、获客准备、探索计划和实验反馈属于私人数据，不进入公开研究导出。

## 4. 统一质量模型

### 4.1 证据层、个人匹配层与行动层分离

保留 E1–E3 证据等级，同时新增独立的内容行动状态：

- **可行动**：目标买方、具体问题、最小交付和至少一个可触达渠道较清楚。
- **需补证**：方向有价值，但当前性、买方身份、工时、替代或采购结果存在关键缺口。
- **仅观察**：只有趋势、历史案例、供给推广或泛化问题，暂不足以设计小包。
- **暂不适合**：需求可能真实，但与用户当前时间、技能、预算、沟通、合规或维护条件冲突。

`readinessStatus` 是正式字段，与 E1–E3 证据等级、个人匹配和用户私人状态独立维护。E3 不自动等于可行动，E1 也不自动等于不可行动。每次判断都必须有理由、证据引用、主要阻碍和下一步。

### 4.2 八个质量维度

| 维度 | 必须回答的问题 |
| --- | --- |
| 需求具体性 | 谁在什么场景遇到什么问题？原始讨论具体说了什么？ |
| 当前性 | 当前需求、持续问题、历史案例还是已关闭事项？ |
| 付费信号 | 需求、意向、报价、选人、交付、付款还是复购？谁提供信号？ |
| 最小交付 | 输入、输出、权限、工时、修正次数和排除项是什么？ |
| 获客可达性 | 买方在哪里出现？如何识别？首个动作是什么？ |
| 个人匹配 | IT 能力匹配、时间、预算、语言、会议、售后和合规依据是什么？ |
| 替代与反证 | 原生功能、免费工具、内部人员或低价供给能否解决？ |
| 探索计划 | 周期、阶段目标、投入上限和继续/暂停条件是什么？ |

### 4.3 探索周期

取消固定“两周”限制：

- 简单服务：2–4 周；
- 默认探索：4–6 周；
- 复杂获客、交付、合规或持续维护：6–12 周或更久。

每个方向必须记录主动工时上限、预算上限、阶段目标、继续条件、延长条件和暂停条件。周期可以延长，但不能无限投入。

## 5. 功能模块

### M1：85 个点子内容审计

输入来源、证据、点子、个人匹配和历史，输出结构化质量结果：

- 目标人群与具体问题；
- 证据等级与具体商业信号；
- 当前/历史/已关闭时效；
- 最小可售交付；
- 强替代与反证；
- 个人匹配和未知项；
- 可行动状态、理由、阻碍和下一步。

审计不得修改私人状态，不得补写未知事实。

### M2：证据与内容模板

证据摘要统一记录：

```text
对象：谁提出或经历了什么问题
原始事实：来源明确表达的内容
信号性质：事实 / 作者声称 / 研究推断
商业信号：需求 / 意向 / 报价 / 选人 / 交付 / 付款 / 复购 / 未知
时效：当前 / 历史 / 已关闭 / 日期未知
支持范围：这条证据能支持哪一个结论
不能支持：不能据此推出什么
```

赚钱方式必须落成最小交付包：买方输入、交付输出、工具/权限、工时范围、修正次数、排除项、一次性/阶段性/持续维护性质和未知成本。

不得把供应方报价写成买方预算，不得把选人、作者收入或历史案例写成付款。

### M3：机会获取与研究扩展

后续研究按缺口而不是只按行业扩展，至少使用五类入口：

1. **问题入口**：重复、延迟、返工、合规、交接、对账、维护等具体痛点。
2. **买方入口**：小企业老板、运营、代理商、教培机构、专业人员、社区组织等角色。
3. **交付入口**：固定小包、异步审计、迁移整理、白标交付、持续维护、培训辅导。
4. **渠道入口**：公开采购、项目平台、专业社区、厂商生态、代理商合作、行业协会、线下服务商网络。
5. **反证入口**：免费替代、原生功能、自助解决、低价供给和失败案例。

每轮先确定一个覆盖缺口和一个关键未知，写明为什么查、查哪里、什么结果会改变判断。新来源数不作为完成指标。

### M4：获客路径设计

每个可行动或需补证点子至少补一条获客路径：

```text
目标买方：具体角色/组织
触发场景：什么时候会寻找帮助
渠道：公开采购/项目平台/专业社区/合作伙伴/内容/转介绍/线下入口
识别信号：如何判断对方可能需要
首个动作：准备什么材料或公开回复什么问题
最小服务包：先卖什么，不承诺什么
沟通负担：异步/少量会议/频繁会议/紧急响应
停止条件：什么结果出现后不再继续
```

系统只生成准备材料和建议，不代替用户执行外部触达。

### M5：分阶段探索与反馈

每个方向至少分为：

1. **可行性阶段**：确认问题、替代和最小交付是否成立。
2. **获客阶段**：验证是否能触达买方并获得有效回复、询价或合作意向。
3. **交付阶段**：验证工时、权限、返工、沟通和交付边界。

每阶段保存目标、主动工时、预算、证据、真实反馈和决策。反馈必须来自实际反馈或可复核交付记录。

### M6：看板与私人状态

正式数据库入口切换后，local-web 增加：

- `readinessStatus` 可行动/需补证/仅观察/暂不适合筛选；
- 当前/历史/已关闭筛选；
- 有买方信号/仅供应方信号筛选；
- 有获客路径/缺获客路径筛选；
- 有交付边界/缺交付边界筛选；
- 探索阶段和建议周期筛选；
- 收藏、准备探索、进行中、延长、暂停；
- 私人备注、反馈和下一步；
- 最多 3 个方向的并排比较。

获客路径、探索计划、私人备注、反馈和下一步默认作为私人字段保存，不进入公开研究包。正式入口切换前，不使用浏览器 localStorage 代替私人状态，也不把只读刷新当作操作完成。

## 6. 优先复核范围

### A 类：优先进入候选比较

- 第一优先：国内非技术行业和国内线下小企业的具体买方、近期委托、交付结果和轻量服务边界，补齐当前明显覆盖缺口。
- 第二优先：`IDEA-20261021-011`、`012`、`013` 及自动化/平台集成方向，作为对照和补证方向，不作为本轮首要扩展路径。
- 后续优先：`IDEA-20261022-036` 至 `040`、`041` 至 `046`，按当前性、交付边界和获客可达性逐条复核，不因公开报价直接升为精选。

先补证据，不直接升为精选；不同交付模式保留变体并建立关联。

### B 类：补当前性和独立性

对 E1/E2 条目核验当前是否开放、是否为买方、是否有第二个独立样本、是否有可复制交付和是否存在强替代。

### C 类：降低近期行动优先级

历史 E3、已选人、已关闭项目、供给推广和当前需求不明的条目，保留为历史或反证，记录重新打开条件。

### D 类：暂不适合或观察

对有明确地域、设备、资质、频繁会议、7×24 响应、线下履约或合规冲突的条目，保留原因后降级，不为数量继续补强。

## 7. 质量检查升级

将 `src/research/idea_quality.py` 从“关键词存在”升级为“结构检查 + 复核提示”，程序不替代人工判断。

### 自动阻断项

- 索引 ID、正文 ID、文件路径、标题不一致；
- 证据等级不是 E1–E3，或索引无法识别 `E3历史` 等中文紧贴写法；
- 来源链接不在证据段落；
- 历史、反证/替代、未知项或下一步缺失；
- 可行动状态、个人匹配、时效状态或商业信号使用未定义值；
- 索引证据、点子正文和关联来源不一致。

### 复核提示项

- 证据只有历史或已关闭信号；
- 只有供应方报价，没有买方确认；
- 赚钱方式没有最小交付；
- 没有渠道、识别信号或首个动作；
- 没有工时、沟通负担或维护边界；
- 使用“市场很大”“需求旺盛”“容易变现”等无来源判断；
- 与已有点子在人群、问题和交付结果上高度相似；
- 个人匹配没有时间、技能、预算或沟通依据。

复核提示只生成待处理清单，不自动删除、降级或补写事实。

## 8. 数据契约与展示

建议新增或扩展：

- `readinessStatus`：可行动 / 需补证 / 仅观察 / 暂不适合；
- `evidenceSignals`：需求、意向、报价、选人、交付、付款、复购；
- `recencyStatus`：当前、历史、已关闭、日期未知；
- `minimumDelivery`：最小交付包；
- `acquisitionPaths`：获客路径列表；
- `explorationPlan`：周期、阶段、工时、预算和退出条件；
- `explorationFeedback`：阶段、日期、事实、结果性质和私人可见性；
- `qualityFlags`：机器检查和人工复核提示；
- `relatedIdeaIds`：重复、变体和上下游关联；
- `coverageMetrics`：来源入口、平台、独立作者/企业、行业、人群、地域和证据进展。

公开研究字段和私人计划分离。新字段先在临时库演练，不直接把 Markdown 和 SQLite 同时作为可写权威。

## 9. 实施顺序

1. **审计器升级**：修复证据识别和统计口径，增加复核提示，不改点子结论。
2. **批量复核清单**：为 85 条生成当前性、信号、最小交付、渠道、周期、相似和获客缺口。
3. **A 类内容复核**：处理 011–013、036–046，形成可比较的高价值样本。
4. **模板化补证**：统一证据、最小交付、获客路径和探索周期。
5. **候选比较看板**：最多 3 个方向并排展示质量状态和建议周期。
6. **私人状态入口**：复用 records-history，接入准备探索和反馈。
7. **研究调度优化**：按质量缺口、买方缺口和渠道缺口安排下一轮。
8. **正式入口切换**：完成迁移、公开/私人隔离、备份恢复和回滚验证后再切换。

## 10. 验收标准

- 85 条全部通过新的结构检查，索引与正文的证据统计一致。
- 每条点子都有明确质量状态、理由、主要缺口和可处理下一步。
- A 类条目都具备最小交付、主要阻碍、建议周期和至少一条获客路径。
- 历史、已关闭、供应方报价、买方意向、交付和付款不再混同。
- 能识别并人工处理潜在重复/变体，不自动删除原 ID。
- 用户能从任一点子看到可比较的探索周期、阶段目标和停止条件。
- 研究更新不覆盖私人计划和反馈；公开导出不包含私人字段。
- `STATE`、索引和看板的统计口径有自动检查。
- 研究、资料和看板测试通过，资料检查失败时能指出具体点子和具体字段。

## 11. 不在范围

- 不为了让 85 条全部变成“可行动”而降低质量门槛。
- 不自动联系客户、发帖、投标、购买服务或执行付费实验。
- 不把 E3、报价、选人或作者收入自述改写成付款事实。
- 不删除历史点子；合并只新增关联和理由。
- 不立即开发完整副业产品或公网 SaaS。
- 不在没有对账和回滚方案前切换正式数据库入口。

## 12. 已确认产品决策

1. `readinessStatus` 作为独立于 E1–E3 和个人匹配的正式字段。
2. A 类不先处理自动化交付与平台集成；先补国内非技术行业和国内线下小企业，自动化方向作为后续对照和补证。
3. 获客路径、探索计划、私人备注、反馈和下一步默认保存为私人字段，不进入公开研究包。
4. 缺少获客路径、探索周期或交付边界时，不阻断基础入库；只阻断进入候选或精选，直到缺口有明确处理结果。
