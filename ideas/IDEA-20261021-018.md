# IDEA-20261021-018 广告招牌行业工单 MVP 梳理与后端试点

- 首次收录 / 最近实质更新：2026-10-21（Asia/Shanghai）。
- 类型 / 行业 / 市场：需求梳理、工单状态机与后端试点；广告招牌制作安装；国内。
- 研究状态：待验证；不进入精选，也不代表用户已选择验证。
- 服务对象与问题：依靠微信沟通客户需求、报价、派工和安装验收的广告招牌公司；客户现场照片、尺寸、材质、预算、安装进度和售后记录分散，企业想上线系统但难以判断一期范围、开发成本与后续存储费用。
- 可能赚钱方式（来源事实与 Agent 推断）：来源正在询问外包报价和承接形式；可先按固定范围交付流程梳理、角色/权限、工单状态机、数据字典和可点击原型，再按里程碑实现小程序加后台的后端试点。实际预算、决策权、合同、付款和重复市场规模未知。

## 证据、反证与替代

1. CN01：[广告招牌行业小程序、App 与后台报价咨询](https://www.v2ex.com/t/1219555)，发布 2026-06-11，访问 2026-10-21。E3 采购探索：广告招牌从业者明确描述客户提交现场照片、尺寸、材质、预算和完工时间，公司将需求转为订单并派安装师傅，师傅更新状态和上传施工记录，最后验收或售后；发帖者询问 MVP 报价、个人/团队/公司选择和一期范围，并欢迎有经验的开发者提供报价。它证明有购买探索，不等于已立项、已选供应商或已付款。
2. 同帖一名回复者给出 2–5 万元供应方估价，并建议一期取消独立 App 和视频上传，降低发布、存储和流量负担。这是供给方报价与范围建议，不是买方预算或成交；也反驳了“一期必须做全端和全部媒体功能”。
3. 通用低代码表单、企业微信、现成工单 SaaS、共享表格和继续人工协作都是替代。该项目涉及客户电话、地址和现场图片，真实实施需要权限、保留期限、备份与删除约定；用户每天两小时投入不足以独立承担完整多端项目和紧急现场支持。

## 个人匹配与未知

有条件适合：角色权限、状态机、文件元数据、审计记录和导出接口符合后端能力；先做流程梳理和后端试点可以固定范围、异步推进，并积累安装服务行业模板。完整小程序、App、UI、视频、上架和长期运维明显超出个人两周验证范围，应限定为售前梳理或后端分包。最大未知是行业内第二个独立样本、实际预算、现有工作流、获客方式和客户是否接受分阶段交付。
